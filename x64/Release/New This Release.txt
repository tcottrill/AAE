**The Atari Math Box is now emulated from its microcode.** Battlezone, Red Baron, Bradley Trainer
and every Tempest-hardware game (Tempest, Tempest Tubes, Aliens, Vortex, Vector Breakout, the
Multigame) run the real Am2901 bit-slice microcode from the mapping and microcode PROMs, ported from
the Tempest C port's interpreter, instead of Eric Smith's 1990s functional re-creation. Results are
whatever the board's microcode computes, bit for bit.

- **Romsets must now include the seven mathbox PROMs** (Tempest 136002-126..132, Battlezone / Red
  Baron 036174-01..036180-01 - identical parts). Every standard MAME set already has them. bzonep,
  aliensv and vbrakout are now clones of bzone / tempest and take the PROMs from the parent zip if
  their own lacks them; bradley.zip needs the current MAME version.
- The ROM loader understands 4-bit PROM dumps (ROM_LOAD_NIB_LOW / ROM_LOAD_NIB_HIGH). The six
  microcode PROMs are packed in the order verified against Atari's MBUCOD source - MAME's tables
  pair them the other way round, but MAME never reads them.

**Tempest Multigame is now "tempmg"**, with the same romset layout and filenames as HBMAME, so one
tempmg.zip works in both. The old "tempestm" set and zip are gone. Each bank now reads its own
game's video.ini rect (Vector Breakout's differs from Tempest's), and the bank switch clears the
previous game's picture. tools\make_tempmg.ps1 builds tempmg.zip from whatever zips you have,
matching files by CRC; tools\make_tempmg_readme.txt says where the Cowgill ROMs still live online.

- **Vector Breakout draws again.** Every build since 9/14 showed a black screen: the MAME-style
  mid-list VGGO handling discarded HALT-terminated display lists on the Tempest vector generator.
  (HBMAME has the same fault.) A HALT-terminated pass is now displayed when VGGO arrives while the
  generator is halted; a VGGO while running still discards the partial pass, as Tempest and
  Quantum need.
- Tempest's OUT0 video inverts are now modelled: player 2 on a cocktail gets the 180-degree turn
  the board does. The Cabinet DIP now defaults to Upright (it was Cocktail; if your saved
  cfg\tempest.cfg still says Cocktail, set it back in the DIP menu).
- Fixed a core bug where the last memory region slot was one past the end of the region array.
- Tempest driver cleaned up: the POKEY-protection instrumentation is gone (the POKEY no longer
  needs it), tempest3 (rev 2B) has its checksums, dead code removed.

8/10/26
Release 1.96
**AAE now runs on Linux.** The emulation core was split out from the video, input and sound
engines, and complete new Linux back-ends were written for all three — **no SDL anywhere**. That gets
AAE onto SteamOS and the Raspberry Pi, with a longer-term target of driving a real vector monitor
from a Teensy or Pi. 

- Going forward one of the main OS targets is Steam OS. You can install from the desktop, add roms and artwork in the AAE folders. 
Then right click and add to Steam Game Mode. After first launch in Game Mode, and a reboot (required) the artwork will appear 
and it will look like an installed steam game.

- I HAVE NOT TESTED BUILDING ON A VANILLA LINUX BUILD. 

**Vulkan is now the default renderer.** The entire OpenGL pipeline was rewritten as Vulkan
equivalents, ported over from my own unreleased game engine. OpenGL 3.3 is still there and still 
fully supported — Vulkan is simply what starts by default, and AAE falls back to OpengGL 3.3 on its 
own if Vulkan won't initialize.

- **A new glow shader** — a dual-filter pyramid bloom that finally looks better than my original.
  That's subjective, but I like it, and it's the default now. The classic 8-pass blur is still
  selectable. *(I also burned a ton of time on a phosphor-persistence replacement and they were
  all disappointing, so that one is still on the shelf.)*
- **Controllers** — PS5 DualSense and PS4 DualShock 4 are remapped to the standard Xbox layout,
  and the system button chords (menu, exit, pause) work from any gamepad while generic sticks
  can't trigger them by accident. The same combo engine runs on Linux, so Steam Input's virtual
  pads get working chords too.
- **A Controller Guide screen** — a drawn controller showing the button layout, coin/start
  mapping and the chords. It appears once the first time a gamepad is detected, and any time
  after from **Y** in the game list or the CONTROLLER HELP menu entry.

New drivers: Frogger, and the first-generation Williams games - Defender, Stargate, Robotron: 2084,
Joust, Bubbles, Splat! and Sinistar. The Williams driver comes from MAME 0.53 with the modern ROM
names, and includes the special-chip blitter, the 49-way joystick and Sinistar's CVSD speech.

Many driver cleanups, the pokey was once again updated, hopefully for the last time!
See the build details on how to add roms and artwork to the Steam OS build. 
Many SOUND Updates. 

Note: The new glow shader looks like crap on the PI 5. The old one looks fine but it's too slow, the PI 5 just doesn't 
have enough pixel pushing power. Black and white shader and color raster shaders are disabled as well on the PI.

I wasted a couple of days trying to make a better B/W & Color Vector Shader (again), but it's just not there yet. The line rendering and bloom looks NOTHING like my real Space Duel on a 6100 monitor, when it does, I'll add it.

Finally fixed aspect ratio support in the Raster Games. 
Because of the long HID driver names, I had to correct issues in the INI support, as well as marquee scrolling to the GUI and MENU options.

Cleaned up the SegaG80 driver code. Added a fake dipswitch for the old (smooth, inaccurate) rendering engine because Star Trek bugs me.  
Various Sound, CPU bug fixes (I think I am just about  done there) and other little code fixes.
