10/4/26
Release 2.00

POKEY: new cycle-accurate emulation
- About two weeks of work went into a new cycle-accurate POKEY core
  (c012294), written from the POKEY VHDL, the remastered chip schematics, 
  the Altirra hardware documentation, and timing measured by custom test 
  code running on a real Space Duel PCB.
- Built from the schematics: the RANDOM shift chain, the timed serial port
  and SKSTAT, the keyboard matrix scanner, and an output stage measured from
  the silicon (replaces the old linear DAC).
- AAE talks to the core through a catch-up adapter (c012294_interface),
  which replaces the old C++ POKEY core.
- Space Duel's shield sound is finally emulated accurately. 
- It is about 75 times slower than the old core. Optimizations are coming
  soon.
- Verification isn't finished. A Warlords PCB is needed for the remaining
  hardware checks. (POT Timing)

New games and sets
- Space Invaders Part II (Taito), invadpt2, with the PROM color board.
- Braze Space Invaders Multigame (invmulti, M8.03D), with EEPROM saves.
- Braze Asteroids / Asteroids Deluxe Multigame (astdelbz, astbz11b,
  astdelbz11b), with EEPROM saves.
  *NOTE* The Braze Asteroids Multigame descrambling code is not included at
  this time.
- Tempest Multigame: tempmg (HBMAME layout) replaces tempestm. Each game in
  the multigame keeps its own screen geometry. The make_tempmg.ps1 tool
  builds the set.
- Omega Race (60 fps), omegrace60: a frame-locked 60 fps version of Omega
  Race on the same ROM set, with no ROM patch.
- Star Wars: starwarso added; ROM names now match MAME 0.286.
- Parent/child merged romsets, as in MAME: a clone loads any missing ROMs
  from its parent's zip and matches files by CRC.

Timing: Atari vector games retimed to the boards
- Lunar Lander, Battlezone, Bradley Trainer and Red Baron run at the board's
  exact 246.09375 Hz (was 240 Hz, 2.5% slow). Red Baron and Bradley now
  present at 40 fps like Battlezone.
- Star Wars / Empire Strikes Back: main IRQ at the hardware rate of 246 Hz,
  checked against the disassembly.
- Omega Race / Delta Race: exact 244.140625 Hz (was 250 Hz, 2.4% fast).
- Major Havoc (all sets): IRQ clock at the board's 4882.8125 Hz (was
  2.4% fast).
- Quantum: driver reworked. IRQ is now 240 Hz (was 180 Hz, about 27% slow)
  and the vector generator handles Quantum's mid-list restarts the way MAME
  0.286 does, so the stray fragments, blank frames and the white diagonal
  line are gone.
- Aztarac: the sound CPU's timer IRQ is now 100 Hz (was 40 times too fast).
- Asteroids, Black Widow, Gravitar, Space Duel and the Tempest family stay
  at 240 Hz (2.5% under the board) on purpose, for smooth 60 fps.

Sound
- Demon and QB3 now run the real Z80 + CTC + 3x AY8910 sound board instead
  of samples. Both have perfect audio, and Demon's sounds no longer stick
  on.
- Star Wars / ESB: 6532 RIOT chip and the real sound board handshake, so
  the music no longer cuts out; TMS5220 speech is now correct.
- TMS5220 speech (Star Wars, Major Havoc) is no longer too loud and harsh.
- Speed Freak: engine, crash and horn sounds.
- Most Cinematronics sound overhauled: the Tail Gunner laser loops while
  held, Boxing Bugs music has four volume levels, and Star Castle and Solar
  Quest sounds no longer carry over from the previous game.
- Battlezone: engine and effect samples driven from the sound latch.
- Volumes normalized: new SAMPLE VOLUME and CHIP VOLUME controls on top of
  the main volume, with per-game balance built into the drivers. Volume
  changes made in the pause menu are now kept.

Game fixes
- Speed Freak: steering and gear shift work for the first time and match
  the real steering wheel. It's still very hairy to drive!
- Sundance: holding two keypad keys no longer draws garbage lines.
- Aztarac: input fixed (the joystick X axis was lost).
- Boxing Bugs: the dial was off by one bit.
- Cinematronics: all games use MAME's screen orientation (Solar Quest was
  upside down and mirrored); QB3 settings no longer carry over into the
  next game; Space Wars and Speed Freak controls fixed; coin input matches
  MAME.
- Joust and Bubbles: sprites no longer vanish.
- Vector Breakout shows a picture again.
- Tempest: cocktail mode flips the screen for player 2; the Cabinet DIP
  defaults to Upright.
- Eliminator clones (elim2a, elim2c, elim4, elim4p): crash fixed.
- Warlords: the driver now matches the schematics; POKEY bus timing passes
  the protection checks with the new chip emulation.
- Battlezone input fixed to work with the new POKEY.
- Star Wars driver rewritten: math box and NVRAM from MAME 0.159, ESB memory
  map and slapstic fixes.

Input
- Twin-stick on one gamepad: Black Widow and Robotron fire with the right
  thumbstick. With two pads, the second pad still works as before.
- Aztarac's aim dial also uses the right thumbstick; Start 1 and Coin 1 are
  on gamepad buttons.
- default.cfg format 4: only bindings you changed are saved, so new default
  bindings in a release now reach you. Delete an old default.cfg once to
  pick them up.

Saves (EAROM / NVRAM)
- New ER2055 EAROM chip model for Tempest, Asteroids Deluxe, Black Widow,
  Gravitar, Space Duel, Red Baron, Centipede and Millipede. Saves use a new
  64-byte .nv format, so old high-score files for these games won't carry
  over.
- Battlezone, Battlezone Plus and Bradley no longer keep an NVRAM file (the
  board has no EAROM).

Video and front end
- New 6100 Soft Phosphor color CRT mode (color_enable=2, OpenGL and Vulkan).
- Color vector games start with the color shader off unless the game's ini
  turns it on.
- Lunar Lander: the MAME artwork is removed; custom on-screen vector artwork
  is switched by a fake DIP switch.
- ALT+ENTER out of fullscreen now restores a correctly shaped window for
  vertical games.
- -window and -nowindow command-line options now work.

Under the hood
- 6502 core: cycle-exact bus timing, undocumented opcodes, interrupt fixes
  (passes the Lorenz NMI test).
- Math box: Am2901 microcode interpreter running from the real PROMs
  (Tempest, Battlezone, Red Baron).
- Scheduler: cpu_yield() and per-CPU timers.
- Linux/flatpak build updated, with release and testing build scripts.

- aae.ini: new dvg_engine option block. video.ini: the ripoff section now uses the correct key names.

**The Atari Math Box is now emulated from its microcode.** Battlezone, Red Baron, Bradley Trainer
and every Tempest-hardware game (Tempest, Tempest Tubes, Aliens, Vortex, Vector Breakout, the
Multigame) run the real Am2901 bit-slice microcode from the mapping and microcode PROMs, ported from
the Tempest C port's interpreter, instead of Eric Smith's 1990s functional re-creation. Results are
whatever the board's microcode computes, bit for bit.

- **Romsets must now include the seven mathbox PROMs** (Tempest 136002-126..132, Battlezone / Red
  Baron 036174-01..036180-01 - identical parts). Every standard MAME set already has them. bzonep,
  aliensv and vbrakout are now clones of bzone / tempest and take the PROMs from the parent zip if
  their own lacks them; bradley.zip needs the current MAME version.
- The ROM loader understands 4-bit PROM dumps (ROM_LOAD_NIB_LOW / ROM_LOAD_NIB_HIGH). The six
  microcode PROMs are packed in the order verified against Atari's MBUCOD source - MAME's tables
  pair them the other way round, but MAME never reads them.

**Tempest Multigame is now "tempmg"**, with the same romset layout and filenames as HBMAME, so one
tempmg.zip works in both. The old "tempestm" set and zip are gone. Each bank now reads its own
game's video.ini rect (Vector Breakout's differs from Tempest's), and the bank switch clears the
previous game's picture. tools\make_tempmg.ps1 builds tempmg.zip from whatever zips you have,
matching files by CRC; tools\make_tempmg_readme.txt says where the Cowgill ROMs still live online.

- **Vector Breakout draws again.** Every build since 9/14 showed a black screen: the MAME-style
  mid-list VGGO handling discarded HALT-terminated display lists on the Tempest vector generator.
  (HBMAME has the same fault.) A HALT-terminated pass is now displayed when VGGO arrives while the
  generator is halted; a VGGO while running still discards the partial pass, as Tempest and
  Quantum need.
- Tempest's OUT0 video inverts are now modelled: player 2 on a cocktail gets the 180-degree turn
  the board does. The Cabinet DIP now defaults to Upright (it was Cocktail; if your saved
  cfg\tempest.cfg still says Cocktail, set it back in the DIP menu).
- Fixed a core bug where the last memory region slot was one past the end of the region array.
- Tempest driver cleaned up: the POKEY-protection instrumentation is gone (the POKEY no longer
  needs it), tempest3 (rev 2B) has its checksums, dead code removed.

8/10/26
Release 1.96
**AAE now runs on Linux.** The emulation core was split out from the video, input and sound
engines, and complete new Linux back-ends were written for all three — **no SDL anywhere**. That gets
AAE onto SteamOS and the Raspberry Pi, with a longer-term target of driving a real vector monitor
from a Teensy or Pi. 

- Going forward one of the main OS targets is Steam OS. You can install from the desktop, add roms and artwork in the AAE folders. 
Then right click and add to Steam Game Mode. After first launch in Game Mode, and a reboot (required) the artwork will appear 
and it will look like an installed steam game.

- I HAVE NOT TESTED BUILDING ON A VANILLA LINUX BUILD. 

**Vulkan is now the default renderer.** The entire OpenGL pipeline was rewritten as Vulkan
equivalents, ported over from my own unreleased game engine. OpenGL 3.3 is still there and still 
fully supported — Vulkan is simply what starts by default, and AAE falls back to OpengGL 3.3 on its 
own if Vulkan won't initialize.

- **A new glow shader** — a dual-filter pyramid bloom that finally looks better than my original.
  That's subjective, but I like it, and it's the default now. The classic 8-pass blur is still
  selectable. *(I also burned a ton of time on a phosphor-persistence replacement and they were
  all disappointing, so that one is still on the shelf.)*
- **Controllers** — PS5 DualSense and PS4 DualShock 4 are remapped to the standard Xbox layout,
  and the system button chords (menu, exit, pause) work from any gamepad while generic sticks
  can't trigger them by accident. The same combo engine runs on Linux, so Steam Input's virtual
  pads get working chords too.
- **A Controller Guide screen** — a drawn controller showing the button layout, coin/start
  mapping and the chords. It appears once the first time a gamepad is detected, and any time
  after from **Y** in the game list or the CONTROLLER HELP menu entry.

New drivers: Frogger, and the first-generation Williams games - Defender, Stargate, Robotron: 2084,
Joust, Bubbles, Splat! and Sinistar. The Williams driver comes from MAME 0.53 with the modern ROM
names, and includes the special-chip blitter, the 49-way joystick and Sinistar's CVSD speech.

Many driver cleanups, the pokey was once again updated, hopefully for the last time!
See the build details on how to add roms and artwork to the Steam OS build. 
Many SOUND Updates. 

Note: The new glow shader looks like crap on the PI 5. The old one looks fine but it's too slow, the PI 5 just doesn't 
have enough pixel pushing power. Black and white shader and color raster shaders are disabled as well on the PI.

Code Enhancements this release:
Added my B/W raster monitor shader code from my PetGPT emulator source, I think it looks very nice. (https://github.com/tcottrill/Pet-GPT)
The B/W monitor code seemed lonely, so I added a color raster monitor shader as well. The old bitmaps are still supported. On 4K, I think the color shader looks better then the bitmap version. There are lots of knobs to tweak on both, so you should be able to find something that makes you happy.
I wasted a couple of days trying to make a better B/W & Color Vector Shader (again), but it's just not there yet. The line rendering and bloom looks NOTHING like my real Space Duel on a 6100 monitor, when it does, I'll add it.  
Added multiple mouse, multiple keyboard support, playing close attention to supporting multiple Ultimarc hardware. I have pretty much one of everything made by him in my possession. At this point it's very similar to modern MAME.
Adjusted the Menu with a new Input option to match. 
Updated the Joystick code to support Direct Input 8 so I can support the HID slots there as well. Xbox controllers are still supported with Xinput. 
Finally fixed aspect ratio support in the Raster Games. 
Because of the long HID driver names, I had to correct issues in the INI support, as well as marquee scrolling to the GUI and MENU options. 
Migrated out all the GLEnums and did a hard clean pass on the Opengl Code in preparation for adding Vulkan support.
Cleaned up the SegaG80 driver code. Added a fake dipswitch for the old (smooth, inaccurate) rendering engine because Star Trek bugs me.  
Various Sound, CPU bug fixes (I think I am just about  done there) and other little code fixes.
