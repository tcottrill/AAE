A.A.E. ENGINE
------------------------------------------------------------------------------

Written by Tim Cottrill. Copyright (C) Tim Cottrill, GNU GPL v3 or later.

Everything below is original A.A.E. code rather than emulation of arcade
hardware - it is the engine the emulated machines are displayed and heard
through, and it shares no code with M.A.M.E.

  OpenGL renderer
      Core-profile GL rendering chain: framebuffer pipeline, shader system
      and the shader set itself.
      Vector beam renderer - anti-aliased beam geometry with per-segment
      joins and caps, phosphor persistence and a multi-pass glow cascade.
      Raster path with prescaled render targets, tiled scanline overlay and
      the mono and colour CRT monitor shaders, including shadow mask,
      halation and pixel-exact output sizing.
      M.A.M.E. .lay artwork layout compositor - backdrop, screen, overlay
      gel and bezel layers, with display-time system rotation.
      Vector font engine for the front-end and in-game overlays.

  Vulkan renderer
      A complete second rendering chain, written from scratch on Vulkan 1.3
      dynamic rendering, at feature parity with the OpenGL path and
      selectable at runtime.
      Beam renderer with instanced coverage-anti-aliased geometry;
      supersampled render targets; phosphor trail and dual-filter pyramid
      glow; raster CRT and scanline post chain; streamed raster game
      texture; .lay layout compositor; textured vector shots; per-pass GPU
      timing via timestamp queries; and framebuffer readback for
      screenshots.

  Audio engine
      Mixer and voice mixer with sample streaming, and 2D positional audio.
      Backend-neutral audio interface with an XAudio2 implementation on
      Windows and an ALSA / PulseAudio implementation on Linux, the latter
      including matrix surround encoding for stereo output.

  Input layer
      Unified joystick and gamepad layer over XInput and WinMM, with
      hotplug detection, rumble, and edge-triggered button combos.
      Win32 Raw Input support for multiple mice and keyboards, with
      per-player device routing and assignments that stay stable across
      reboots and enumeration changes.
      evdev backend providing the same on Linux.

  Emulation infrastructure
      The CPU cores listed under "Original A.A.E. cores" below, the
      configuration and menu systems, the front-end, and the Windows and
      Linux platform layers.

CPU EMULATION CORES
------------------------------------------------------------------------------

A.A.E. now runs a family of its own CPU cores, written from published
manufacturer documentation and sharing a common memory-handler interface.
These are original work and replaced the third-party engines A.A.E. used
previously.

  Original A.A.E. cores
  ---------------------
    Motorola MC68000 / MC68000E
        From-scratch, per-instance C++ implementation of the original
        MC68000, written to replace the Musashi engine.

    Motorola MC6809 / MC6809E
        Documented instruction set, written for A.A.E.

    Intel 8039 / MCS-48
        Clean-room implementation, written from the published Intel MCS-48
        User's Manual and 8039 datasheet. Not derived from other cores.

    Sharp LR35902
        The Game Boy's 8080/Z80 hybrid, written for A.A.E.

    Intel 8085A
        Extended to a full 8085A from the A.A.E. 8080 core. Cross-checked
        against the Intel 8085A datasheet and the M.A.M.E. I8085 core by
        Juergen Buchmueller.

  Cores with earlier origins
  --------------------------
    Zilog Z80
        Original Z80 emulator by Edward Massey (1997), ported to C by
        Jeff Mitchell.

    MOS 6502 family
        Original 6502 core by Neil Bradley.

    Intel 8080
        Written by Mike Chambers (2018), copyright (C) 2010-2013
        Mike Chambers.

    Zilog Z80 family peripherals (CTC and friends)
        Copyright (C) 1997 Tatsuyuki Satoh.

    Cinematronics CCPU
        See the vector hardware section above.

Atari POKEY
    The current A.A.E. POKEY is a clean-room reimplementation. It stands on
    the shoulders of Ron Fries, whose original POKEY emulator defined this
    field and whose channel-rendering approach informed the design.
    M.A.M.E.'s POKEY device: Brad Oliver, Eric Smith, Juergen Buchmueller.

    M.A.M.E. device by Couriersud, based in turn on code snippets by
